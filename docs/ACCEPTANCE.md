# 交付标准（v1）

- 产品：`synology-frp`，群晖 DSM 7.4 套件（仅 x86 机型）
- 版本：v1.0 / 2026-11-23
- 状态：**已确认，开发中**

## P1 简述

**做**：把本仓库的 `frpc`（当前源码 0.72.0）编成 DSM 套件；在 DSM 窗口里用一个纯文本编辑器改配置，点保存即校验并重启 frpc；页面同时显示运行状态与最近日志。

**不做**：frps 服务端、端口映射/反向代理的可视化管理、配置项图形化表单、多实例与多配置文件、非 x86 架构。

**交付物**：可安装的 `.spk`、源码与一键自动化测试、安装说明、指向 `dev` 的 PR。

## P2 验收用例

### A. 安装与窗口

**US-01 装得上、打得开、卸得掉**
> 作为 NAS 主人，我希望它像普通群晖应用一样装和用。

- 手动安装后主菜单出现图标，点击在当前 DSM 窗口内打开（不需要二次登录），窗口标题与图标正确。
- 仅 x86 机型可安装；ARM 机型不会出现在可安装列表里。
- 所有 DSM 用户都能看到并打开；权限由 DSM 自带机制管，套件内不另设账号。
- 卸载后图标消失、后台停止，**配置文件与日志保留**（重装能接回），NAS 上其它东西不受影响。

**US-02 打开就有一份能改的配置**
- 首次打开，编辑器里已有一份带注释的示例配置（服务端地址、端口、一个 TCP 代理示例）。
- 页面明确提示「把 serverAddr 改成你自己的服务器地址」这类必须先改的地方。
- 文件真实存在于套件的私有目录，不是只存在浏览器里。

### B. 编辑与保存

**US-03 改完能存**
- 在编辑器里修改后点保存：内容被写入磁盘；关掉窗口重开，看到的还是我改后的内容。
- 保存内容为空或只有空白 → 拒绝保存并提示，磁盘上保留上一次的有效配置。
- 编辑器支持粘贴大段配置（2000 行以内不卡死），保存后回读一致。

**US-04 保存即重启**
> 作为用户，我不想去点第二个按钮才生效。

- 点保存后：frpc 进程确实重启（进程号变化，重启后状态显示「运行中」）。
- 重启期间不需要我关闭窗口，页面自动刷新状态。
- 如果配置里只有注释/空行改动、frpc 照样能起来，不算失败。

**US-05 配置写错要看得懂**
> 作为用户，我写错一个字段名时，希望直接看到 frpc 的报错，而不是「保存成功」的假象。

- 配置语法错误导致 frpc 起不来时：保存动作仍会把我的内容写盘（不丢我的修改），但页面明确显示「已保存，但启动失败」并附上 frpc 的原始报错。
- 此时状态显示「已停止 / 启动失败」，不会显示「运行中」。

**US-06 只有一个生效的配置文件**
- 界面只维护一个 `frpc.toml`；保存后磁盘上不会同时出现两个配置文件。
- 想换用旧的 INI 格式时，把文件手动改名为 `frpc.ini` 即可，后端会按实际存在的文件识别（界面不提供格式切换，避免把窗口做复杂）。

### C. 运行控制

**US-07 状态一行可见**
- 窗口里有一行状态：运行中 / 已停止，以及是否已连上服务器、版本、已运行时长。
- 保存失败时，弹窗直接给出 frpc 的原始报错。
- 日志不占窗口（按你的要求保持窗口精简）：文件在 `/var/packages/synology-frp/var/logs/frpc.log`，或用静态排查页查看；日志会按 2 MB 自动轮转。

**US-08 手动控制**
- 停止、启动、重启三个操作即时生效，状态随之变化。
- 停止后配置不被改动；重启不丢配置。

**US-09 NAS 重启后自动恢复**
- NAS 重启后，套件随之启动并且 frpc 自动拉起，用的还是上次保存的配置。
- 上次配置本身就是坏的 → 套件照常启动，页面显示启动失败原因，不会卡住 DSM。

### D. 放心用

**US-10 出错了看得懂**
- 任何失败都给人话说明 + 可复制的错误信息，不出现白屏或英文堆栈。
- 页面上「连不上后台服务」时给出可执行的排查步骤（含手动反代片段），而不是空白页。
